# FinMan v2.2.1.3 — Changelog

---

## ✨ New Features

### Credit Card Account Type
- Added **Account Type** field to account settings with `Regular` and `💳 Credit Card` options.
- Credit card accounts store a **Settlement Date** (day of month the billing cycle closes, 1–28) and **Payment Due Days** (days after settlement date, 1–30).
- Input validation enforces valid ranges with clear error messages.
- Live preview of current billing cycle and next due date shown while editing.

### Credit Card Billing Cycle View (Accounts Screen)
- Credit card accounts display a **two-column row** — `Balance Payable` and `Outst. Balance` — instead of a single net balance.
- Column header labels appear above CC rows in every group containing a credit card account.
- Account group headers for all-CC groups show combined payable and outstanding totals.

### Credit Card Billing Cycle Logic
- **Balance Payable** = total charges from all closed billing cycles minus all payments made to date. Payments reduce this first.
- **Outstanding Balance** = net charges in the current open billing cycle. Overpayments spill over from payable and reduce this figure.
- When the card is overpaid beyond current cycle charges, Outstanding Balance shows a green `+` credit amount.

### CC Cycle Period in Account Drill-down
- Credit card accounts default to a new **CC Cycle** period tab in the drill-down view, scoped to the current billing cycle.
- CC Cycle is navigable with ‹ › arrows to browse past cycles. A **Current** badge marks the live cycle.
- A billing info strip shows the cycle's closing date.
- CC Cycle tab is hidden for non-CC accounts; all other period tabs remain available.

### Grouped Account List in Settings
- Settings → Accounts **List view** now organises accounts by Account Group in the same order as the Account Groups section.
- Each group renders a section header with an account count badge.
- Accounts within a group are indented for visual clarity.
- An **Ungrouped** section at the bottom collects accounts with no assigned group.
- Credit card accounts show a `💳 Credit Card · settles Nth` hint line inline without needing to open the edit panel.

### Profile Card in Settings
- Profile and PIN Lock moved to a prominent card at the top of the Settings screen, matching the app's visual identity.
- Card shows the user's avatar initial, name, and PIN lock status at a glance.
- Tapping anywhere on the card or the Edit button opens the Profile & Security screen.
- Separate "Profile & Security" row removed from the settings list.

### Dynamic Chart Windows
- Account drill-down and Category drill-down trend charts now anchor to the **viewed period** rather than always showing the last 6 months from today.
  - **Month view** — last 6 months ending at the viewed month.
  - **Year view** — last 6 years ending at the viewed year.
  - **FY view** — last 6 financial years ending at the viewed FY.
  - **All / Custom** — chart hidden (no fixed window applies).
- Chart title updates accordingly: *6-Month Trend*, *6-Year Trend*, *6-FY Trend*.
- Analytics bar chart Month view similarly anchors to the selected month.

### Full Backup Export (JSON)
- JSON export renamed to **Export Full Backup**. In addition to all transactions, the backup now includes accounts (with groups, CC config, settlement dates), account groups, account mappings, categories (with subcategories), and budgets.
- Backup file carries a `_finman_backup` marker and version tag for reliable detection on re-import.

### Settings Restore on JSON Import
- Importing a Full Backup JSON automatically restores accounts, account groups, account mappings, and categories before processing transactions.
- Import mode prompt shows **Merge (recommended)** as the primary action — keeps all existing transactions and settings, adds only new rows.

### Backup Feature
- New **Backup** section in Settings → Data with three capabilities:
  - **Backup Now** — saves a full JSON backup to device storage instantly, logs entry to backup history.
  - **Auto Backup schedule** — choose Daily, Weekly, Monthly, or Off. A reminder banner appears above the bottom nav on app open when a backup is overdue per the chosen schedule.
  - **Backup history** — shows the last 3 backups with filename, date, and file size.
- **Google Drive** row shown as Coming Soon, explaining OAuth setup requirement for future implementation.
- `lastBackupCheck` is updated only when an actual backup is taken, not when the schedule is changed.

### Running Balance in Account Drill-down
- Each transaction in the account detail view now shows the **cumulative account balance after that transaction**, displayed in brackets below the amount — e.g. `(₹9,67,413)`.
- The most recent (top) transaction of the entire viewed period shows a `Balance` prefix: `(Balance ₹9,67,413)`.
- Works for all account types including credit cards. Negative balance shown as `(−₹4,027)`.

### Credit Card Payment Due Date Alerts
- **Alert banner** appears on the Accounts screen when any credit card has a payment due within 7 days. Shows card name, countdown, exact due date, and current Balance Payable.
- Color-coded urgency: 🔔 yellow (3–7 days), ⚠️ orange (1–2 days), 🚨 red (overdue). Each banner is dismissible per-card for the session.
- **Due date dot** on the credit card account row shows days remaining (e.g. `5`) or `!` if overdue.
- Due dates are computed from Settlement Date + Payment Due Days configured per credit card account.

### Searchable Picker for Account and Category Selection
- Native `<select>` dropdowns for Account, From Account, To Account, and Category replaced with a **searchable bottom-sheet picker**.
- Each picker opens a sheet with a live search box and two sections: **Recent** (last 5 distinct values from transaction history, auto-computed — no setup needed) and **All** (full alphabetical list minus recent items).
- Currently selected value shown with a ✓ check. Searching instantly filters both sections.
- Subcategory retains the native select (typically 3–5 items, no scroll needed).

### Configurable Content Font Weight
- New **Content Font Weight** selector in Settings → Appearance with three options: Light (400), Regular (500), Bold (700).
- Applies to transaction notes, amounts, account names, balances, category names and amounts — leaving structural text (headings, labels, buttons, date headers) at fixed weights.
- Default is **Regular (500)**. Setting persists across sessions.
- Implemented as a single CSS variable `--fw-data` applied at the `<html>` level — no per-component prop drilling.
- Live preview in the Appearance screen shows a mock transaction row that updates instantly on selection.

## 🐛 Bug Fixes

### Credit Card False Positives on Account Name
- Auto-detection of credit card type from account name is now limited to the word `credit` only. Previously `card` and `cc` were also matched, causing accounts like Food Card, Debit Card, and Prepaid Card to be incorrectly treated as credit cards.

### Account Type Not Persisting on Save
- Fixed a bug where setting an account to `Regular` did not persist after saving.

### CSV Export — Multiline Fields Breaking Row Structure
- The CSV exporter now quotes any field containing a newline or carriage return (RFC 4180 compliance). Previously, Description or Note fields with embedded newlines were written unquoted, causing subsequent rows to be misaligned in the file.

### CSV Parser — Quoted Multiline Fields
- The CSV parser was rewritten to a character-by-character RFC 4180 tokeniser. The previous implementation split the entire file on `\n` before processing quotes.

### Import — Phantom Accounts and UUID Categories
- Overflow rows from old corrupted exports produced entries like `Account='INR'`, `Category='<UUID>'` in the database after import.
- Fixed by: skipping rows whose date does not normalise to `dd/mm/yyyy`; filtering reserved words; filtering UUID-shaped strings from category and account names.

### Import — Duplicate Categories from Case Mismatch
- Category names were matched case-sensitively during import, causing `online shopping` and `Online Shopping` to be stored as two separate entries. Category merging is now case-insensitive.

### Import — UUID Category Names Persisting in DB
- UUID strings left as category names from previous bad imports are now detected and purged from the category table at the start of every import.

### Import — `Subcategory='Default'` Stored as Real Subcategory
- The value `Default` written by Money Manager for Transfer rows was being stored as a real subcategory name. It is now stripped to an empty string on import.

### Import — Transfer Destination Resolution
- Import now prefers `ToAccount` (FinMan format) and falls back to `Category` (Money Manager format) only when `ToAccount` is absent or a reserved word.

### Account Mapping Always Empty in JSON Export
- `getAccountMapping()` was not called in `load()`, so `state.accountMapping` was always `undefined`. Fixed — account mappings are now loaded into state and correctly exported and restored.

### Copy Transaction — Original Date Not Preserved
- "Copy with original date & time" always used today's date because `handleCopy` in both `Accounts.jsx` and `Transactions.jsx` was overwriting `Date` and `Time` before the picker appeared. Fixed — the copy picker in `DetailSheet` now has sole responsibility for setting the date.

### Note Clear Button (✕) Not Visible on Focus
- The ✕ button on the Note field now appears as soon as the input is focused, not only after text is entered.

### Subcategory Percentage Badge
- Subcategory percentage badges now always show, including a `100%` badge on the **All** row. Previously the entire section was hidden when no subcategories existed.
- Each subcategory badge is colour-coded using the same `PIE_COLORS` palette as the main category donut chart.

### Backup Due Banner Not Showing After Schedule Selection
- Selecting a schedule was incorrectly resetting `lastBackupCheck` to the current time, preventing the banner from appearing. Fixed — `lastBackupCheck` is now only updated when an actual backup is taken via Backup Now.

### Font Weight Selection Not Reflecting in Appearance Screen
- Selecting a font weight updated the CSS variable immediately (so text in the app changed) but the selected card in Appearance did not highlight until a page refresh. Fixed by adding a dedicated `SET_FONTDATAWEIGHT` reducer case that updates `state.fontDataWeight` at the top level, matching the pattern used by theme and font family.

### Version Number in About
- About screen version updated to `v2.2.1.3`.

## 🏗 Notes
- DB schema: `accounts` table extended with `acct_type`, `settlement_date`, and `payment_due_days` columns. Existing Android (SQLite) databases migrate automatically via `ALTER TABLE` guards. Web (IndexedDB) version bumped to `7`.
- CSV import is **transactions only** — account groups, CC configuration, categories, and mappings are not carried in CSV format by design. Use **Export Full Backup (JSON)** for a complete portable backup.
- Recommended import workflow after deploying this release: export a fresh Full Backup JSON → clear data → re-import JSON using Merge. This eliminates any UUID categories or duplicate case categories that accumulated from previous imports.
- Google Drive backup requires a Google Cloud project with OAuth2 consent screen and SHA-1 app fingerprint — planned for a future release.
- Version: `2.2.1.3`
