# FinMan v2.2.1.4 — Changelog

---

## ✨ New Features

### Instalment Transactions (Expense only)
- Tap the **🔁 Rep/Inst** button next to Date/Time when adding an expense to set up an instalment.
- Enter the duration in **months or days** (e.g. 84 days or 3 months).
- Choose a **scheduling mode**:
  - **On the day** — same date each month (e.g. 22nd Mar, 22nd Apr, 22nd May).
  - **Start of month** — proportional split: remaining days this month, then 1st of each following month. Ideal for recharge cycles.
- The total amount is split **proportionally by days** across all instalments. Rounding differences are absorbed into the last instalment so the total is always exact.
- All instalment transactions are created immediately and deducted from the account.
- Each transaction note is tagged with its part number: `Test (1/4)`, `Test (2/4)`, etc.
- Note autocomplete strips part suffixes so `Test` appears as a clean suggestion.

### Repeat Transactions
- All transaction types (Expense, Income, Transfer) can be set to repeat.
- Frequencies: Daily, Weekly, Every 2 weeks, Monthly, Every 3 months, Every 6 months, Annually.
- Scheduling modes: **On the date** or **Start of month** (snaps to 1st of each period).
- The first transaction is saved immediately. Each subsequent occurrence is created automatically when the app is opened on or after the due date.
- Upcoming repeat transactions are processed silently at 00:00 of the due day.

### Instalment & Repeat UX
- **Rep/Inst button** appears next to Date and Time in Add Transaction (add/copy mode only).
- A green summary badge below the date row confirms the active recurring config and can be dismissed to clear it.
- A 3-step bottom-sheet guides through: Type → Duration/Frequency → Schedule mode.

### Instalment Edit Behaviour
- **Editing non-Amount fields** (Note, Category, Account, Subcategory, Description) on an instalment applies the change to **all sibling transactions** sharing the same rule. The `(x/n)` part tags are preserved.
- **Editing Amount** updates only that single instalment. The rule's recorded total adjusts by the difference.
- The detail view shows a `📋 Instalment (2/4)` badge so the user always knows which part they are viewing.

### Instalment Delete Behaviour
- **Delete this instalment only** — removes the selected transaction; others remain.
- **Delete all instalments** — removes every transaction in the series and cancels the rule.

### Recurring & Instalments Management (Settings)
- New **Recurring & Instalments** section in Settings shows all active, paused, and completed/cancelled rules.
- Each row shows: type, base note, amount, duration/frequency, schedule mode, next due date, and instalment progress bar.
- Actions: **Pause / Resume** (repeat rules), **Cancel rule** (with confirmation).
- Cancelling a rule keeps existing transactions; only prevents future occurrences.

### Recurring Rules in Backup
- Full Backup JSON now includes all recurring rules.
- Importing a Full Backup restores recurring rules alongside transactions and settings.
